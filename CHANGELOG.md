# Changelog

All notable changes to this project are documented here. The format is
based on [Keep a Changelog](https://keepachangelog.com/en/1.1.0/), and the
project adheres to [Semantic Versioning](https://semver.org/spec/v2.0.0.html).

## [Unreleased]

### Changed (UI)

- **Dataset header actions and rail reworked** (dv-gs5) — the rail is now three plain buttons (Dataset Checks / File Checks / Response) that only navigate; the DOI chip is the external Dataverse link, with the curation-label chip beside the publication status. Load/Reload Metadata moved into the Dataset checks section header, Download Dataset / Verify Files into the File checks header, and Export reports was removed. The primary button is state-aware (Run Automatic Checks → Run File Checks → Re-run Automatic Checks) and stages the dataset first when nothing is staged. The frozen app was rebuilt.

### Changed (tooling)

- **Documentation is built from Markdown by Zensical (dv-l1f, ADR 0009)** — the hand-authored HTML pages are replaced as the published source by a Markdown tree in `docs/` built with a native `zensical.toml` (explicit nav mirroring the 10 live page names, two frozen proposal snapshots out of nav and marked historical, Mermaid diagrams and theme-derived CSS). `zensical` is a dev dependency; `poe docs` builds strictly and `poe docs-serve` previews. CI builds the site on every PR and publishes to GitHub Pages at `isaacpratt.github.io/dataverse-curation-app` on master pushes only. README, AGENTS.md, SECURITY.md and the package metadata now point at the Pages URL. The old `docs/html/` tree stays as a frozen reference until the planned Diátaxis rewrite (dv-uq6); edit Markdown from now on.
- **All application code is type-checked under full `--strict`; only tests relax** (dv-a4w, ADR 0008 supersedes ADR 0007) — the documented `ui.*` relaxation is withdrawn, so `engine/`, `curation/`, `ui/`, `main.py` and the in-scope `tools/` helpers all satisfy the same strict contract. The four test packages relax only `disallow_untyped_defs`, `disallow_incomplete_defs` and `disallow_untyped_decorators`; `check_untyped_defs` and every other strict check stay on. One override block, four flags, four test packages. The ~959-error burn-down added annotations only — no runtime behaviour, copy, geometry or layout changed — and the test helpers carry parameter annotations so they remain callable from checked bodies. ADR 0007 is marked superseded and the development guide's type-check section records the new policy.

### Fixed (UI)

- **Check boxes look like check boxes** — the kit's indicator was a 16px box with a half-height radius filled with the accent colour when checked: a solid blue circle, the visual language of a radio button, with no check mark at all. It is now a 16px rounded square (4px corners, `BORDER_CONTROL` edge) carrying the Lucide `check` glyph in `ON_PRIMARY` when checked, with distinct unchecked, checked, disabled and hover faces. `make_checkbox()` keeps its signature (it returns the kit's `AppCheckBox`, still a `QCheckBox`), every existing call site is unchanged, and `ui/tests/test_checkbox_face.py` checks the rendered pixels at 2x.
- **Structural Qt warnings fail the build** — a stylesheet Qt cannot parse is dropped with one warning and no exception, so the widget quietly renders without its face. That is how a badge built without explicit role colours lost its face: one fragment inside the f-string was left as a plain string, so the sheet ended with two closing braces. The sheet is fixed, and unclassified Qt messages are now a failure rather than a line on stderr: the probes install a message handler (`tools/probes/_common.py`, summarised by `run_all.py`) and pytest-qt fails the emitting test (`qt_log_level_fail = "WARNING"`). Exactly two messages are allowlisted, both from the offscreen environment rather than the app. `probe_qt_warnings.py` proves the gate by provoking a broken sheet, and `ui/tests/test_kit_stylesheets.py` checks every sheet builder for balanced braces and no unsubstituted `{TOKEN}`. Both gates caught real bugs on their first run: a `QBoxLayout::insert` index that was out of range for a header with no title yet.
- **A rule row is chosen by a click, never a hover** — the Review configuration field tree passes `hover_tint=False` to `AppTreeWidget` (which threads a `hover` flag into `theme.selection_qss`), so a pointer passing over a row no longer paints a band that reads as "this is the one" while the Response pane targets another rule. Other tables and trees keep the shared hover tint; a guard test pins both halves. Selection is now explicit: `itemPressed` on any column, and a press routed from a dropdown or its cell host through an event filter, both call `_select_row(item)` — it sets the current row, reads the rule from the row's `UserRole` data and retargets the pane. Arrow keys move the current row through `currentItemChanged`; block/group headings are ignored. `ui/tests/test_review_config_selection.py` drives QTest mouse moves, clicks and keyboard navigation, and `tools/probes/probe_review_selection.py` checks the pixel under the pointer and saves a screenshot.
- **Review configuration has two rule cards** — the former single "Checks" card (a field tree, a divider and an in-card "Text rules" heading) is now two sibling cards in the left pane: "Metadata Field Rules" (the field table, its filter/level/collapse tools row, now named `FieldRulesTools`) and "Content-based Rules" (the text-search list with its own Add/Edit/Delete row and an "N rule(s)" summary). Both have their own (i) tip; the divider and the old headings are gone, the page footer keeps the field count, and the right-hand Response text card is unchanged. `ui/tests/test_review_config_cards.py` and `tools/probes/probe_review_cards.py` pin the titles, the order, the 16px gap and the single pane scrollbar at 1440 and 960.
- **Entry-check params read as a form** — the "Looks plausibly correct" panel is no longer a squeezed `QFormLayout`: each short label sits above its full-width control, with 8px between rows and the five flags one per row. Minimum length uses the kit's Lucide minus/plus stepper, Blocked phrases and Allowed values use the kit's one-phrase-at-a-time chip fields, Whole value moved onto its own checkbox line, and every explanation (including the fail-closed sentence) became a tooltip on the label and control instead of painted help text. The panel follows the engine's reading order; the loader/editors still block signals and drop empty keys, so saved JSON is unchanged. The Response pane has a minimum width so no control clips at 960px. `ui/tests/test_review_config_params_layout.py` and `tools/probes/probe_review_params.py` pin one-line labels, whole steppers, aligned chips and no horizontal scrollbar at 1440 and 960.
- **Dataset checks and File checks are the two top-level sections** — the dataset page's flat card list became a Dataset checks section (a `make_section_heading` above the Metadata check and Automated checks cards) followed by a File checks section (the renamed File Manifest card). The Automated checks card now lists only `report.dataset_checks` with a summary scoped to that list; every per-file finding lives solely in the File checks folder → file → check tree, which gained its own passed/warn/errors/skipped summary. The skipped-many collapse was dropped by decision — the File checks status filter already narrows those rows, and duplicating them in both sections was the reported defect. Dataset disposition keys are unchanged (dataset rows still use an empty path), so saved dispositions survive the move. The rail's Checks step jumps to the Dataset checks heading; the two filters remain separate. `ui/tests/test_two_check_sections.py` and `tools/probes/probe_check_sections.py` pin the heading order, single listing, scoped summaries and a full file tree at 1440 and 960.

### Changed (layout)

- **The review rules table owns one row shape** — every field row of Review configuration is a 40px row whose two 32px dropdowns are vertically centred (4px above and below) in the fixed order **Field | Level | Check**; the table has no header band, no reset control and no user column sizing, and it never needs a horizontal scrollbar at 1440x900 or 960x720. The Check dropdown (Must be non-empty / Looks plausibly correct / a specialised handler) moved out of the Response pane into the row, so that pane holds response text and the entry-check params only. A new kit helper `make_cell_control()` centres a control in a cell (margins alone would not centre a fixed-height child), column widths are measured from the widest item each column can show — with the themed chrome polished, and over every handler label for the Check column, since a combo's `sizeHint()` measures only its current item — and the dropdown columns are `Fixed`, so no gesture exists to persist and the old `TableLayout("review_fields")` had nothing to save. Each row's `UserRole` data is the single owner of the rule it edits, so selection and both dropdowns cannot drift; block/group headings carry no data and no cell widget, so they can never become the edited rule. `ui/tests/test_review_config_table.py` pins the shape, `tools/probes/probe_review_table.py` adds the pixel-level checks and screenshots at both widths.
- **The kit gains a number field and a multi-value chip field** — `make_number_field()` is a bounded spin box between two 32px Lucide minus/plus ghost buttons (the native stepper was clipped at the right edge of a 32px field; it is switched off, typing is allowed and clamped, and the buttons disable at the bounds), and `make_value_list()` takes one phrase at a time — Enter or a plus button adds it, each entry is its own chip with a Lucide x that deletes just that entry, the chips wrap when narrow, blanks and case-insensitive duplicates are ignored, and an optional empty-state caption names what the list is for. Both share `make_icon_button()`, the body of `make_reset_columns_button` extracted so the stepper, the chip delete and the column reset cannot drift. `AppNumberField.setValue` never emits (the params loader sets values by hand), so the raw-input guard now lists `QSpinBox`/`QDoubleSpinBox` and names the kit builder — Review configuration's minimum-length field is the last raw spin box and is converted. `ui/tests/test_number_field.py`, `ui/tests/test_value_list.py` and `tools/probes/probe_gallery_inputs.py` pin the contract, and the gallery shows both controls (number: normal, at a bound, disabled; list: two chips plus the empty state).
- **Every mark is a bundled Lucide glyph** — `ui.icons.ICON_ROLES` names one glyph per role (refresh, back, sidebar show/hide, more, add/remove, done, the sort and expand chevrons), `role_icon()` resolves it, and three kit builders carry the shapes: `make_icon_button()` (icon only), `make_icon_text_button()` (glyph plus label) and `make_refresh_button()` (rotate-ccw plus its label, used by the queue and the Log page). The copy-this-finding button is the `ellipsis` glyph instead of a `⋯` character, the progress ring paints the Lucide `check` (and `triangle-alert` when it fails) instead of a typed mark, the dataset sidebar toggle shows `panel-right-close` / `panel-right-open`, Extensions' Reinstall leads with `rotate-ccw` (and Install with `plus`), and About's Close shows `arrow-left`, because it navigates back rather than dismissing. Four assets were added in the existing face (`panel-right-close`, `panel-right-open`, `ellipsis`, `arrow-left`). `icon()` now warns once for an unknown name instead of returning a silent null icon; `ui/tests/test_icon_inventory.py` fails on an unresolved name or a glyph-character button, and the gallery has an icon sheet (every glyph at 16 and 20px) that `tools/probes/probe_icon_sheet.py` checks for real ink. The Windows caption buttons and the column-drag cursor stay as they are, both documented exceptions.

### Changed (engine)

- **Every check declares its scope** — `Check.scope` (`"dataset"` or `"file"`) says what a check's findings are about; `extensions` now only says which files it reads. The dispatcher routes on the declaration (`dataset_level_checks()` and `checks_for_file()`), `list_planned_checks()` reports `scope` so a caller can group the "will run" list by it, and the registry refuses a class that does not declare one — so a cross-file check can read `.csv` and still report once for the dataset, and a new check cannot inherit an accidental answer. All 24 checks declare theirs (4 dataset, 20 file); the report JSON is unchanged.
- **The application core moved to `curation/`** — the loose root modules (`applog`, `config`, `dashboard_cache`, `download_manager`, `metadata_check`, `response_draft`, `review_rules`, `storage`) and the `client/` package now live under `curation/`, which is the middle layer the dependency graph already had (ADR 0006). `main.py` stays the single entry point for both the GUI and `--headless`, and the PyInstaller builds are unchanged. The `dataverse_client.py` compatibility shim is gone — the app is not a library, so the old absolute paths were rewritten in place instead of being kept alive by a re-export. A new import-linter contract keeps `curation/` free of `ui/` and `PySide6`: the table-layout sort direction is persisted as a plain `int` in `curation.storage` and converted to `Qt.SortOrder` in `ui/table_layout.py`.
- **The dataset detail page was split into sections** — `ui/dataset_detail.py` (4,419 lines, the largest module in the repo) is now the `ui/dataset/` package: `page.py` is the facade (layout, splitter, signals) over ten section mixins (metadata, metadata loading, checks, files, versions, the dataset log, the response draft, the actions, the header, the workflow rail), all sharing one typed contract in `state.py` (`DetailState`: the attributes the page owns, the page's signals, and the calls the sections make across each other) and the shared formatting helpers in `helpers.py`. The facade is imported as `from ui.dataset import DatasetDetailView`; the rendering and the copy are unchanged. A new test pins the split: every cross-section call the contract declares must be implemented by a section, and no section module may grow past 1,000 lines.
- **Signing policy decided** — distributed Windows builds will be signed through **SignPath Foundation**, a managed signing service that signs open-source Windows software for free: no institutional certificate to buy or hold, and no key material in the repository. The signing step is wired in `dv-4t6.6` and skips cleanly when the `SIGNPATH_*` secrets are absent, so forks and local builds are unaffected. The first releases stay unsigned with a published `SHA256SUMS.txt`, a documented SmartScreen click-through in the user guide, and a checksum check. The policy, the cert source and the renewal story are recorded in `SECURITY.md` and linked from the release workflow.

### Changed (tooling)

- **mypy `--strict` on the engine contract** — the scope in `[tool.mypy] files` (`engine/`, `curation/`, plus the engine test suite) is now checked under `--strict`, with no per-module ignore list. 44 strict-subset errors were fixed by annotating the engine, the client and the core services.
- **The UI layer is type-checked too** — `ui/` and `main.py` joined `[tool.mypy] files` (dv-hcg.28, ADR 0007): 308 mypy errors in the view layer are now 0. The ramp rewrote 252 forgiveness-mode enum aliases to their scoped PySide6 names (`Qt.CursorShape.PointingHandCursor`, `Qt.ItemDataRole.UserRole`, `QHeaderView.ResizeMode.Interactive`, …) and fixed the shape bugs the census listed: an `int(QSize)` that was never a width, a mixin calling methods it never declared, an attribute annotated in one place and redefined in another, `itemFromIndex` called on `QAbstractItemModel`, and functions used for their return value. `ui.*` is checked under a documented relaxation of `--strict` (the "annotate everything" rules off, `check_untyped_defs` and every shape check on) because PySide6 ships no usable stubs for the widget tree; `main.py` keeps the full strict settings.
- **Dependency direction is machine-enforced** — `poe contracts` (import-linter, also in `poe check` and CI) forbids `engine/` → `ui/`/`PySide6`, `curation/` → `ui/`/`PySide6` and `tools/` → `ui/`. The engine contract has no exceptions: the dashboard cache helpers the engine tests used to borrow from `ui/dashboard.py` moved to the Qt-free `curation/dashboard_cache.py`, so `engine/tests/` no longer imports the view layer and joined the strict mypy gate.

## [0.2.0] - 2026-11-16

### Changed (tooling)

- **uv is the package manager** — `uv.lock` is the source of truth; `uv sync --group dev` creates the environment; the committed lock is enforced by `uv lock --check` in CI and pre-commit; `requirements.txt` is gone; the app builds as `uv sync` without producing a wheel (`[tool.uv] package = false`); PEP 639 metadata (SPDX `MIT`, repository/docs/issues URLs, authors, classifiers); Python floor aligned to 3.11 (`.python-version`, CI).
- **poe (poethepoet) is the task runner** — `poe check` (lint + format check + typecheck + tests), plus `poe fmt`, `format-check`, `audit`, `hooks`, `license-report`, `sbom`, `docs-links`, `probes`; cross-platform task definitions.
- **pre-commit is the local gate** — check-only hooks: JSON/TOML/YAML validation, large-file/case-conflict/merge-conflict/Windows-illegal-names, private-key detection, whitespace/EOF fixers, codespell (Canadian English), `uv lock --check`, ruff, actionlint, and a `forbid-config-json` guard aimed squarely at the token file.
- **Ruff format is adopted** (whole tree, enforced in CI/pre-commit/`poe check`); ruff rule set extended (pep8-naming, ruff-specific, simplify, pytest-style, mccabe `max-complexity=12`, import hygiene); docstring rules (D103) active.
- **CI** runs on windows-latest with SHA-pinned actions: pre-commit, ruff, engine coverage gate (75%), `compileall`, headless smoke, UI probes, workflow lint, and an OSV dependency audit of the locked set (failing). Dependabot opens grouped weekly update PRs.
- **pytest** runs with `--strict-markers` and `xfail_strict`; the global `RuntimeWarning` suppression was removed (there was nothing to hide).
- **Coverage gates**: repo total ≥ 65 (actual 68.9%, branch), engine ≥ 75 (actual 77.3%).

### Changed (app)

- **Token storage**: the API token now lives in the OS credential store (Windows Credential Manager via `keyring`, keyed by instance base URL); `config.json` keeps only `api_token_source: "keyring"` with a blank token. Load precedence is env > keyring > plaintext; legacy plaintext tokens migrate on first save; clearing the token in Settings deletes the credential store entry; log redaction now also masks `Authorization: Bearer`, `X-Dataverse-key`, `Api-Key` and `password`/`secret=` patterns; log line format gained `WARN`.
- **Configuration**: `config.json` gains `version: 1`; schema validation reports the exact field on bad shapes (values, types, sections) instead of silently coercing; writes only canonical keys (legacy `collection_alias`/`subtree` are read-only migration inputs); env overrides (`DATAVERSE_BASE_URL` — https + host required, `DATAVERSE_API_TOKEN`, `DATAVERSE_COLLECTION`, `DATAVERSE_WORKSPACE`) are validated/normalised; docs carry a one-table env reference and an on-disk artefacts reference.
- **client/ package**: `dataverse_client.py` (2,836 lines) decomposed into `client/` (`constants`, `errors`, `http`, `parsers` (pure payload parsing), `caches`, `downloads` (`_DownloadsMixin`), `client` (session/discovery)); `dataverse_client.py` remains a compatibility shim — every existing import works unchanged.
- **Agent hygiene**: `AGENTS.md` is canonical (`CLAUDE.md` points at it; stale "454 tests" copy removed); `.editorconfig` added; root module-size guideline; binary assets untouched under `.gitattributes` (`uv.lock` is `-diff linguist-generated`; `config.json` is `-diff -text`).
- **Docs**: README rewritten (quick start, doc index, license); `SECURITY.md` added (token handling, reporting, dependency/CVE policy, threat model); `development.html` gains an on-disk artefacts map, an environment-variables table, corrected coverage numbers and the whole-tree format gate; `docs/html` gained an offline link check (advisory in CI).

### Fixed

- `storage.py` datetime: `timezone.utc` → `UTC` alias (py311).
- `poe typecheck` was red (pre-existing mypy errors); the engine contract gate is green again.
- Pillow 13 compatibility (surfaced during the mypy run).

## [0.1.0] - 2026-10 (untagged initial packaged builds)

### Added

- Desktop GUI (PySide6): dashboard queue, dataset detail, Settings, About, Log, Review configuration panes.
- Engine: 22 format checks ported from `CUR_Res_CurationTools` (MIT) — CSV, XLSX, SAV, DTA, SAS7BDAT, JSON, XML, IPYNB, SQLite, HDF5, NetCDF, GPKG, TIFF, images, PDF, text/code, containers, FASTQ, Secrets, Access checks; dispatcher + runner; missing optional libraries degrade to warnings.
- Dataverse client: total-driven paginated discovery, lock-based in-review detection, enrichment (inventory, sizes, depositors), guestbook flow, bundle + original-format downloads with checksum verify, curation-label bulk report, version compare.
- Local SQLite state (WAL), in-memory request log with token redaction, component-kit UI with theme token contrast contract, 513 tests, UI probes, and PyInstaller lite/full builds.
