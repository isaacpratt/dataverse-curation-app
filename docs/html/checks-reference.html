What PASS means (two contexts)

WhenBadgeMeaning
Before running (Auto-Checks card)PASSCheck is planned and applicable to this dataset's files
—No matching files for this check
MISSINGOptional library absent in this build
After running✓ passed:truePolicy held (info results typically pass with details, e.g. “consistent 12 columns”)
✕ FAILerror-level finding — data integrity problem
✕ warningFinding to review with the researcher
○ SKIPPEDSub-check could not run (details.skipped: missing lib, encrypted PDF, legacy .xls, size caps) — distinct from a pass
Always-emit: every module emits all owned IDs every run — passes like “No zero-byte files” and “no PII values detected” stay visible in the manifest tree and Markdown. Finding lists are capped (secret_max_listed=20, pii_max_samples=10); the message always states the truncation (showing first 10 of 47 sample(s)) and details.count carries the full total.

Download verification (a gate, not a check)

Before checks run, DownloadManager.verify() rehashes every staged file against the Dataverse checksum (md5/sha1). Mismatches surface as checksum mismatch: <path> with expected/actual hashes. Tabular .tab derivatives are server-regenerated, so their message includes the file's UNF for manual comparison instead of failing byte-exact.
