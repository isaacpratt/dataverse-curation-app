Quality gates

CI (windows-latest) runs, via uv run and the committed lockfile: pre-commit run --all-files (EOF/whitespace, JSON/TOML/YAML, secrets, codespell, uv lock --check, check-only ruff, actionlint), ruff, pytest with engine coverage, compileall, the headless smoke (.github/workflows/ci.yml) and an OSV vulnerability scan of the locked set (tools/audit_deps.py). GitHub Actions are pinned by commit SHA; Dependabot (uv + github-actions weekly, pre-commit monthly) proposes updates (.github/dependabot.yml). Locally: uv run poe check (lint + typecheck + tests), uv run poe lint, uv run poe format-check (phase-1 set), uv run poe audit, uv run poe hooks, uv run poe typecheck, uv run poe probes, uv run poe license-report, uv run poe sbom, uv run poe docs-links. mypy is in the dev group; the full configured coverage (uv run pytest --cov, branch coverage) is 68.9% (gate 65); CI measures the engine subset (77.3%, gate 75); both gates raise over time as UI coverage improves.

poe typecheck gates the engine contract: engine/ plus the Dataverse-facing modules it feeds (dataverse_client, download_manager, storage, review_rules, metadata_check, applog) — scope lives in [tool.mypy] files, so run bare uv run mypy. engine/tests/ is excluded on purpose: it imports the PySide6 view layer, and PySide6's stubs expose enums only under scoped names (Qt.CursorShape.PointingHandCursor, not Qt.PointingHandCursor), so including it would bury the engine signal under ~170 Qt-only attr-defined errors. Typing the UI layer is tracked separately.

The repo pins its toolchain with uv.lock and .python-version (3.11), so every PyInstaller build resolves the same dependency set; a stale lock fails CI's uv lock --check before anything builds. The hook set is check-only (no auto-fixers other than whitespace/EOF fixers). core.hooksPath is beads-managed, so hooks are not auto-installed; run uv run pre-commit run --all-files manually, or rely on the CI step.

Startup timing

The window paints its shell before the cached dashboard, local state reads or any network call: main.py shows the window, processes the first frame, paints it synchronously and reveals it, then calls MainWindow.start_background_load(). Until that reveal the window is cloaked out of DWM composition, so neither an empty client nor a native title bar can flash on screen. Settings, About, Requirements and Log are built on first navigation (their scroll pages join the stack then). To see where a launch spends its time, point DOCENT_STARTUP_LOG at a file; every phase appends one row (total ms since process start, ms since startup_probe import, label), and the total includes the PyInstaller bootloader:

$env:DOCENT_STARTUP_LOG = "$env:TEMP\docent-startup.log"
dist\curation-app-lite\curation-app-lite.exe
Get-Content $env:TEMP\docent-startup.log

Warm onedir launches reach first paint in roughly 0.9-1.1 s on the reference machine; cold launches pay an antivirus pass over the ~160 MB folder. The probe is inert (one environment lookup per mark) when the variable is unset.

Interface text (string catalogue)

All user-visible interface copy lives in one UTF-8 JSON file: ui/assets/strings.json. Modules never spell out UI wording; they look it up through ui/i18n.py.

FileRole
ui/assets/strings.jsonThe catalogue. Nested objects give each screen a namespace (app, common, status, dashboard, detail, review, settings, download, log, checks, workers, main, ring, about, dialogs, workflow). Values are plain strings; {name} marks a placeholder filled at the call site.
ui/i18n.pyt(key, **values) renders one string, tn(key, count, **values) picks a plural variant, has/keys/reload support tooling and tests. A missing key returns the key itself, so a typo degrades instead of crashing a screen.
ui/status_text.pyMaps the engine's stable classifier keys (passed, failed-warning, failed-error, skipped) onto catalogue entries, so the GUI never reads the engine's English labels back as data.
ui/tests/test_strings.pyFails the build when the catalogue and the code drift apart: unknown keys, missing placeholders, values that cannot format, a module that hard-codes interface copy again, catalogue entries nothing references (an orphan entry is rot — it looks like live copy but no screen can show it), and any prose literal in the interface layer that neither the catalogue nor the structural allowlist owns.
from ui.i18n import t

self._btn = AppButton(t("detail.header.download_all"))
self._status.setText(t("detail.status.metadata_loaded", count=len(inventory)))

Conventions. Keep the English wording byte-identical when moving a string — the existing tests assert exact copy. Escape literal braces as {{ / }}. Namespaces follow the module that owns the text (detail.* for ui/dataset_detail.py); shared words such as common.save, common.cancel and status.badges.* are reused rather than duplicated. ui/assets already ships through the existing --add-data "ui/assets;ui/assets" PyInstaller rule, so frozen builds need no extra packaging step.

Keys must be static. Build the key at the call site, never from a fragment: t(f"main.caption.{kind}") hides the key from the string test, so a rename would render the raw key in the title bar. Keep a small lookup table instead (_CAPTION_KEYS = {"min": "main.caption.min", …}) — the test then sees every key as a plain string and can prove it exists.

The prose sweep catches text that travels. The call-based scan cannot see a title and message packed into a tuple and shown later, so test_strings.py also reads the literals themselves: anything that reads as words in ui/ or main.py must be in the catalogue or in the allowlist, which carries one line per exception and the reason it stays. CSS, HTML, SQL, URLs, date formats, regexes and key sequences are recognised by shape or by the call they are passed to.

Out of scope. The engine and the report contract are deliberately not externalised: check messages, result levels and the JSON/Markdown report fields are data consumed by other tools, not interface copy. QSS, object names, internal dictionary keys, URLs and format identifiers stay in code. The headless CLI messages in main.py are catalogue entries under app.cli.

Data tokens stay in code. A few strings look like copy but are part of a machine contract, so they are shared constants rather than catalogue entries: the dataset state token dataverse_client.STATE_IN_REVIEW (rendered by the dashboard through dashboard.display_state.review), the Dataverse state names compared by the status filter (DRAFT, PUBLISHED, IN REVIEW, DEACCESSIONED), the cache-slot token behind dashboard_cache_key(), the "no label" filter sentinel, and the network-error needles in ui/dialogs.py that are matched against raw exception text. Translating any of them would change behaviour, not just wording.

UI conventions

The shared kit in ui/widgets.py and the theme in ui/theme.py are the only sources of the app's look. A new view builds its controls through the kit; it does not invent its own stylesheet.

RuleHow
One table and tree contractAppTable (a table), AppTree (a model-driven tree) and AppTreeWidget (a tree with cell widgets) — see Table component contract. A view that needs a different table subclasses one of them, it does not build a QTableWidget from scratch.
One layout ownerTableLayout (ui/table_layout.py) per header. Never wire sectionResized straight to a save: a programmatic fit would overwrite the user's layout. A change counts as a user gesture only when the user could have caused it — the kit ignores a section the layout owns (stretch, fixed, or a stretched last section).
One type scaleA label wears a token (its object name is the token) or takes its size from the theme's FONT_* constants. A raw font-size: Npx outside theme.py fails ui/tests/test_type_scale.py.
One heading contractmake_page_heading() for a full-page title, make_section_heading() inside a page, make_card_title() on a card. All of them set an object name; none writes an inline stylesheet.
One reset affordancemake_reset_columns_button(name) — the same ghost button with the rotate-ccw icon everywhere.
Colours come from the themeNo hex literal outside ui/theme.py (enforced by ui/tests/test_theme_tokens.py).
Palette, then role, then componentOnly ui/theme.py and ui/widgets.py may name a palette entry. A view names a role (SURFACE_CARD, TEXT_DANGER, ACCENT_PRIMARY) — what the colour is for. The kit builds the component. A theme swap is then a table edit, not a hunt through views.
One contrast contractThe pairings the app paints live in theme.CONTRAST_PAIRS and theme.BADGE_CONTRAST_PAIRS, with the ratio each must clear (text 4.5:1, graphics 3:1, disabled 3:1). ui/tests/test_contrast.py reads that table, so a palette change that breaks legibility fails the build. Add a pairing there rather than leaving it implicit at a call site.
One button systemmake_action_button(text, kind=..., size=...) for every action button. The app-level rule and the widget-level copy both come from theme.button_qss(), so they cannot drift. The kinds are primary, secondary, ghost, chip, cell (a table action cell), link (a left-aligned brand row that navigates) and nav-active/nav. Never call action_button_style() from a view, and never hand-write a QPushButton rule.
Labels wear tokensSet the object name (HeadlineLG, BodyMD, CaptionSM, MonoSM, HintSM, AccentSM, SuccessSM, WarningSM, DangerSM, LabelStrongSM) or use the kit's label builders; never paint a label's colour or size. A label whose text changes at runtime changes its object name and re-polishes.
No inline stylesheets in a viewA view asks the theme for a rule (page_background_qss(), transparent_surface_qss(), surface_frame_qss(), input_qss()) or the kit for a component. A literal or an f-string in a view fails ui/tests/test_theme_conformance.py. The one escape is an explicit # theme-allow: marker on the line, with a reason.
Kit-only inputsmake_line_edit(), make_search_field(), make_multiline_input(), make_plain_text_view(), make_list(), make_checkbox(), make_progress_bar(), make_combo(). A view never constructs a raw QLineEdit, QTextEdit, QListWidget, QCheckBox, QProgressBar, QComboBox or QPushButton.
One badge vocabularymake_badge(text, label=...) — the label picks the role, so two badges of the same family never drift apart. Pass explicit role colours only when the badge is a known state (PASS / FAIL / SKIP).

Component gallery

The gallery (ui/gallery.py) shows every kit component on one page: the type scale, the role swatches, the button kinds and sizes, the badge roles, the standard inputs, the containers and the data components. It is the app's visual contract in executable form — when the theme changes, the gallery changes with it.

python main.py --gallery          # open the gallery
python -m ui.gallery               # the same, standalone

The gallery is itself a view, so it obeys the same rules as every other one: it names roles, not palette entries, and it builds components, not raw widgets. It is also the first thing to look at when a component looks wrong, because it puts that component next to every other one instead of in the middle of a page.

Adding a component? Add it to the kit, then add it to the gallery. tools/probes/probe_gallery.py checks that the gallery still builds, still shows a component of every kind, and that every button in it wears one of the theme's button object names — the gallery may not show a button the app cannot produce.

Qt pitfalls

The bugs this app had were mostly Qt behaviours working exactly as documented. These are the ones that bite.

PitfallWhat Qt doesWhat to do
A widget-level stylesheet shadows the app-level oneSetting a stylesheet on a widget replaces the application stylesheet for that subtree. The app's QHeaderView::section rules stop applying inside a table that has its own sheet.Repeat the rules from the theme's mixins: header_section_qss(flush=) and scrollbar_lane_qss(scope=) in ui/theme.py. One source, so the two sheets cannot drift.
sectionResized fires before the new size landsReading header.sectionSize(i) inside the handler returns the old value. A synchronous copy persists stale widths, and the last column's label drifts off-centre.Defer the work: QTimer.singleShot(0, self._fit_queue_columns).
Children are not clipped to a parent's border-radiusA table flush inside a card paints its own corners, so a rounded card edge shows a notch where the table's square corner sits.Flush tables and trees paint square top corners (they meet the card's top bar) and take the card's bottom radius themselves; the header's end caps stay square for the same reason.
A filled scrollbar lane paints over the card's cornerThe vertical scrollbar's lane inherits the page colour, so the card's border ends in a white notch at the bottom right.Keep the lanes transparent (scrollbar_lane_qss) so the card's own surface shows through; thumbs and grooves keep coming from the global theme.
An ancestor's background bleeds through a transparent widgetA styled lavender ancestor makes a table body transparent, and the rows render page-coloured instead of white.Set the background explicitly in the widget's own sheet (flush_table_style()).
Qt derives cell-widget geometry from the item content boxWith a stylesheet active, the app's QTableWidget::item rule (padding + border) shrank every action cell, clipping the buttons inside it.Zero the vertical padding for the action cells (QTableWidget::item { padding: 0px 12px; }).
QHeaderView.lastVisibleSection() does not exist in PySide6Calling it raises AttributeError.Walk the header: logicalIndex(v) over the visual range, then isSectionHidden(logical).
App-level QSS does not reach a label that has its own stylesheetThe label's own sheet wins for the properties it sets; the app's token rule still supplies the rest, but a label that sets font-size itself has left the type scale.Set the object name to the token and leave the stylesheet empty — that is what make_* builders do.
The offscreen platform has no fontsEvery glyph renders as tofu, so a text measurement says nothing.Verify layout by geometry and pixels (section sizes, viewport widths, corner colours), never by the rendered text.
Native sort indicator straysThe style CE_HeaderSortIndicator paints at section top-centre under the header QSS, not beside the label; no QSS position or nested QPainter fixes it.Use SortArrowHeaderView (ui/widgets.py) — arrow as child-label overlay, refreshed on paint; stock sort state is kept.
QFont point size vs QSS pixel sizesapply_theme() sets QFont point size 9 while QSS tokens paint 11–22px; measures and paint disagree, elision can drift.Known open mismatch, tracked as bead dv-06b.
A QThread destroyed while it is still running aborts the processQt prints QThread: Destroyed while thread is still running and calls abort(). A worker parented to a widget dies with that widget — so quitting the app while the extensions scan is walking the installed packages killed the process, and an offscreen probe that ended with a worker live died the same way.Register every worker with ui.workers.register_worker() and check isInterruptionRequested() between steps. Two hooks stop them: QApplication.aboutToQuit (the app quitting) and an atexit hook (the process ending without a clean quit). The registry lives in ui/workers.py; a new worker class must register itself.

UI probes

The probes in tools/probes/ are the pixel-and-geometry checks behind the table bugs. Each one runs offscreen against a throwaway workspace, prints a PASS/FAIL line per check and exits non-zero on a failure.

python tools/probes/run_all.py                # every probe, one command (what CI runs)
python tools/probes/probe_queue_columns.py    # the queue's columns fill the viewport, never clip
python tools/probes/probe_manifest_columns.py  # the manifest fits, persists the user's widths, resets
python tools/probes/probe_headings.py          # every full-page heading wears the same token
python tools/probes/probe_card_corner.py       # a card's bottom-right corner stays connected
python tools/probes/probe_buttons.py          # the app sheet and the scoped sheet agree, kind by kind
python tools/probes/probe_gallery.py           # the gallery builds and shows every kit component
CI runs the probes. The workflow has a second job, probes, that installs the requirements and runs python tools/probes/run_all.py offscreen. The runner executes every probe_*.py and exits non-zero when any of them failed, so the pixel-and-geometry checks are part of the build rather than a habit.
The temp-workspace rule. A probe must never write to the user's workspace/table_layout.json: a probe that saves there leaves the real app with a layout nobody chose. tools/probes/_common.py:boot() points cfg.app.workspace at a fresh temp directory and applies the theme; every probe goes through it. A new probe must do the same, and must stub out anything that would reach the network (the manifest probe replaces _on_load_metadata).

The same contracts live in ui/tests/ as pytest suites, so CI runs them: test_table_layout.py (the controller), test_table_geometry.py (the queue's geometry), test_page_headings.py (the heading contract), test_type_scale.py (the type scale), test_contrast.py (the contrast contract) and test_theme_conformance.py (the layering guards). The probes stay useful for the things pytest cannot see — a pixel colour at a card's corner, a screenshot to eyeball.

python -m pytest ui/tests -q        # the UI contracts
python -m pytest engine/tests -q    # the engine contracts
python -m ruff check ui/           # lint

ui/tests/conftest.py provides a session-scoped qapp and win (one offscreen application, one main window). The window is shared, so every test sets its own preconditions; a test that needs the dashboard on screen calls win._show_dashboard() first — the queue's fit is a no-op while the table is hidden.

Planned: dark mode (beads epic: dv-4jm)

Dark mode is not implemented. It is tracked as beads epic dv-4jm (children dv-zds → dv-m2q → dv-m8m → dv-q7t → dv-ceb). Open the epic with bd show dv-4jm; it is the next planned step in the UI standardisation, recorded here so the ordering is explicit. Everything below is groundwork that is already in place; the work itself has not started.

The reason it is now possible at all is the role layer. A dark theme is not a second set of colours scattered through the views — it is a second role table. The palette stays a palette (PRIMARY is still #004ccd); the roles decide what each palette entry is used for, and the role table decides which palette entry each role points at.

What a dark theme needs, in order:

  1. A second role table. The roles become a mapping rather than a flat set of aliases: TEXT_PRIMARY points at the light surface's ink in one theme and the dark surface's ink in the other. A theme switch is then a table swap, not a re-skin.
  2. A second contrast contract. The floors do not change (text 4.5:1, graphics 3:1), but the pairs do: every role pair in CONTRAST_PAIRS is re-declared for the dark theme and checked by the same test. A dark palette that fails legibility fails the build exactly as a light one does.
  3. The app stylesheet, per theme. theme.global_qss() becomes global_qss(theme), and the kit's component chrome follows. The QSS that hardcodes a surface (the card faces, the scrollbar lanes, the table rows) is the part that has to be re-pointed at roles first.
  4. The painted assets. The icons are tinted from a role, which already works; the app mark and the taskbar icon are the exception and need a dark variant.
  5. The gallery, showing both. The gallery is where a theme is reviewed, so it should be able to show the light theme and the dark theme side by side. Every contrast decision becomes a glance instead of a judgement call.

Two things are deliberately not planned yet: a theme picker in Settings (the role table makes it possible, but it is a UX decision, not a refactor), and automatic switching by the operating system (the same, plus a preference to persist).

What is already done. The palette/role split, the contrast contract and its test, the one button system, the conformance guards, and the gallery. None of them needs redoing for dark mode — they are the work that makes it a table edit instead of a re-skin.

Conventions

  • Python 3.10 typing, dataclasses; no external framework in engine/ (stdlib + listed deps). Checks are pure functions of local files — no network I/O inside engine/.
  • Module-per-format naming mirrors the R scripts; keep Report contract in sync with schema changes — it is the interface between engine and GUI.
  • Selectable dialogs (ui/dialogs.py:show_warning/show_critical/show_info) for traceback-bearing errors; log every request via applog.log_response; the Log page's QSyntaxHighlighter paints ERROR red, WARNING yellow, IPs, SQL keywords, XML tags, Java backtraces.
  • Parent every QThread to its view, chain deleteLater, adopt before discarding (MainWindow._open_dataset) — never destroy a live QThread.
  • Theme: no hardcoded hex outside theme.py (enforced by ui/tests/test_theme_tokens.py).
  • Layers: palette → role → component. Only theme.py and widgets.py may name a palette entry; a view names a role and builds components (enforced by ui/tests/test_theme_conformance.py).
  • Legibility: every pairing the app paints is declared in theme.CONTRAST_PAIRS / theme.BADGE_CONTRAST_PAIRS and checked (enforced by ui/tests/test_contrast.py).
  • Buttons: one system. make_action_button() in a view, theme.button_qss() as the single generator, never a hand-written QPushButton rule.
  • Labels: tokens, not painted styles. The object name carries the token and the theme owns the rule; a label that changes at runtime changes its token.
  • Type scale: no raw font-size: Npx outside theme.py (enforced by ui/tests/test_type_scale.py); a label wears a token.
  • Tables: one controller per header (ui/table_layout.py); only user gestures are persisted; a programmatic fit runs inside layout.suppressed().
