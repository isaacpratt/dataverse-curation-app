User guide

The Dataverse Docent is a desktop tool for curators reviewing datasets deposited in a Dataverse instance: first run, dashboard queue, dataset detail, response drafts, log, troubleshooting, headless mode.

First run

  1. Launch (dist/curation-app-lite/curation-app-lite.exe or python main.py). With no config.json, the Settings page opens automatically.
  2. Choose the Dataverse: preset (Borealis Demo — demo.borealisdata.ca or Custom…; the Base URL field stays editable), API token (blank = public-only browsing; drafts/in-review need a token), Collection alias (e.g. mcmaster; empty = whole repository; the demo root alias is dv — aliases root/:root are treated as empty, verified against Borealis v6.8.4-SP), Workspace folder. Test connection hits GET /api/info/version before saving.
  3. Extensions tab: per-package Install/Uninstall with installed sizes for optional curation libraries, plus Tesseract (OCR) and ExifTool (deep metadata) paths.
  4. Save → the app contacts the instance (paginated GET /api/search?q=*&type=dataset&per_page=100&start=…&subtree=… with dedup) and the dashboard loads; the bottom status pill shows the current Dataverse + collection. Switch instances anytime via top-nav Settings (Ctrl+,) — Save applies config.json and reloads the dashboard, Back discards; the last choice is persisted next to the exe (see config.example.json). ? opens About. Headless/CLI runs ignore --dataverse/--config (local staged directory only).

Dashboard (curation queue)

Lists datasets from paginated Search (100/page, up to 1000). All 12 columns are sortable (numeric/date-aware _SortItem), draggable, resizable with visible edge dividers (hover/press highlight), and togglable via right-click header or Columns…. First paint auto-fits content (proportionally downscaled on overflow — the queue has no horizontal scrollbar); dragging any edge locks your widths; Columns… → Reset columns && sorting restores defaults and re-enables auto-fit (saved widths always win across restarts). Status and Curation Label render as plain text.

Filter bar: free-text search (title, ID, contact, depositor, collection, curation label) + Status (All / Draft unsubmitted / Published / In Review / Deaccessioned — draft markers anywhere in the search record count) + Curation label (All + the instance's own set + No label) + Collection (All + every subcollection in the pull). The label set is pulled fresh on every refresh via the Curation Status API — bulk report first, then the allowed set from draft datasets (retried across several, since the endpoint needs PublishDataset permission) — and remembered in <workspace>/curation_labels.json; the dataset page header shows the label as a pill with setter/time tooltip. Instances without labels configured just show “All Curation Labels” + “No label”.

The queue is cached per instance+collection (dashboard_cache.json): instant paint on open, background refresh reports only what changed (N new, M updated, K removed / No changes — N datasets up to date). The status pill at the bottom of the dashboard carries <base URL>/[<alias>]: X/Y datasets shown (instance scope + filtered count), then — after a dot — the contextual message (“Double-click a row to open it”, load progress, or an error); the row ends with the 16×16 Docent mark at the bottom-right. Double-click (or Enter on the focused row — use the visual row's Persistent ID after sorting) opens a dataset; F5 refreshes; Escape clears search.

Other controls: Refresh in the queue header (re-runs the paginated crawl), Review configuration in the top nav (edit review rulesets + response templates in requirements_profiles.json), the Log toggle (Ctrl+L), ? (About). Without a token only published datasets return; the first-run empty state offers a primary Open Settings action and metrics read — until the first crawl.

Curating a dataset

Metadata check shows rule-driven completeness for the selected ruleset (McMaster derived from the McMaster Curation Log / Depositor Checklist — source PDFs retired 2026-10-07, rules live in code — or Minimal, plus any custom rulesets). Each row is Check (bold) / Value / Status (✓ Complete green vs ✗ Incomplete red, requirement in the tooltip) with a summary X/Y fields complete (ready for review / needs attention). Value is what the depositor entered; Requirement describes the profile's expectation. Includes per-author ORCID format checks (every author needs a valid ^\d{4}-\d{4}-\d{4}-\d{3}[\dX]$), an Author count row (N authors: A; B (+M more)), a License and Terms of Use row (license name + termsOfUse/termsOfAccess), and README detection via the file inventory. The Value column drag-resizes against Status; changing the profile re-evaluates immediately.

Review configuration (top nav) edits the rules: the left column marks each metadata field from the Dataverse metadatablocks catalog as Required / Optional / Not checked and manages text-search rules (filenames, metadata values, staged file contents — e.g. README); License / Terms of Use / Terms of Access group under License and Terms of Use; the right column edits the standard response text per rule plus the draft header/footer. Rulesets apply per Dataverse (* = all instances), are stored as requirements_profiles.json v2 next to the executable, and show a ● unsaved chip while edited.

File Manifest lists every file (staged dir if downloaded, else the Dataverse inventory) with most of the column width. Columns: Name (folder › file › check tree), Size, Format, Scan. Restricted files, embargo/retention dates, and tabular ingest status/errors appear in the name/scan tooltips. Click a row after checks for its findings; Open folder reveals the staged directory. The Raw metadata bottom toggle shows citation blocks plus a — Full JSON — dump (capped 12000 chars) from GET /api/datasets/:persistentId.

Notes on checks

  • Checks matching the file format run automatically; files with no applicable check (unknown extension) are listed but not inspected (no checks).
  • Lite build covers JPG/PNG/PDF/XML/XLSX/TIFF offline (Pillow, pypdf, lxml, openpyxl, tifffile, chardet) + stdlib image-header fallback when Pillow is absent. Only heavy binary libs (pyreadstat, netCDF4, h5py, scipy) need the full build — run dist/curation-app-full/curation-app-full.exe directly for SPSS/SAS/Stata/NetCDF/HDF5/MAT. Missing libs report Missing … in the Auto-Checks area as a warning CheckResult, never a failure.
  • OCR (PDF text extraction) and deep exif are optional: without tesseract/exiftool they report “not executed”.
  • Parity with the R inspectors is held by 262 tests (engine port; pytest --collect-only -q for the live count). Semantics: checks reference.

Log and troubleshooting

The Log stack page (nav Log button or Ctrl+L) shows an in-memory ring buffer (applog.py) of every Dataverse request (GET <url> → <status> (<ms>) <summary>) plus worker messages, stamped in local time. INAV-style highlighting colors ERROR red, WARNING yellow, IPs, SQL keywords, XML tags, Java backtraces, and quoted strings (lines with ERROR/WARN get higher priority). The header carries the severity legend (ERROR/WARN chips in the highlighter's exact fills plus a muted INFO · DEBUG plain key, so colour never explains itself), a Search log… box (case-insensitive substring; the Live tooltip shows match counts), a ● Live toggle (pause to freeze — click again and buffered lines catch up), Clear, and hide. The panel polls every 800 ms (QTimer) while live; the full-page Log view and the Log dialog carry the same search box. All error dialogs (ui/dialogs.py) are selectable for pasting tracebacks.

Headless mode

python main.py --headless <staged_dir> --out report.json
python main.py --headless <staged_dir> --out report.json --persistent-id doi:10.5072/FK2/EXAMPLE
python main.py --headless <staged_dir> --out report.json --format both --persistent-id doi:10.5072/FK2/EXAMPLE

Same engine/runner.py:run_report without the GUI. --format json|md|both (default json) also writes the Markdown view. --dataverse/--config are GUI-only and rejected here. Exit codes: 0 clean, 1 error-level findings, 2 usage/IO failure.
