Why Python, not portable R

Bundling portable R was evaluated and rejected as a last resort: base R is ~100 MB and the required packages (tidyverse, haven, exiftoolr, …) push a portable install to ~400 MB. The Python engine ships at ~70 MB (lite zip, ~158 MB unpacked) with identical pass/fail semantics — verified by parity tests, not by inspection.

Status

Phase 1 complete: 21 check modules ported and verified; 291 tests passing. Run pytest --collect-only -q for the live count (200 engine + 91 UI). MATLAB .mat (Scripts/Inspect_mat_Script.R → scipy.io) stays deferred to keep scipy optional — mat_check.py does not exist; .mat files surface via inventory.unchecked_types. If added, it would be lazy-imported like the other heavy libs.

containersR targets compressed archives (.zip/.tar/.7z), not container images; Python follows that scope + testzip + encrypted-member detection

csvDelimiter sniffing with comma fallback; ragged/duplicate/email-PII mirrors the health-check report

images / tiffSynthetic fixtures (no raster samples in CUR data); tiff uses tifffile
Missing libslevel="warning" “check not executed — pip install …” (Auto-Checks tab: Missing: pip install …), enabling the lite build

Go / no-go criteria (spike — met)

Prototyped the three hardest formats first (sas7bdat, gpkg, nc/hdf5). Go when (1) every R check has a Python equivalent with the same pass/fail semantics, (2) both engines yield the same findings on the same data/ samples, (3) runtime on the largest sample stays within 2× of R. Single-format failure degrades to documented “not executed” instead of blocking; portable R fallback only if multiple formats fail — not needed.

Maintenance

The R book stays the authoritative reference; the Python engine is the runtime. Parity tests (pytest -q, CI .github/workflows/ci.yml) are the contract keeping them in sync and must run in CI as the R scripts evolve.
