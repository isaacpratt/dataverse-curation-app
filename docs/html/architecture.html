Threading model

The GUI thread never blocks. Workers are parented to their views with deleteLater chained on completion; a discarded detail view's live workers are adopted by the main window — a live QThread is never destroyed. One check run at a time per dataset; results persist as DatasetReport so a crash loses nothing. The Log page polls on an 800 ms QTimer (Live toggle, gated to page visibility, search debounced at 200 ms).

Missing optional dependency → CheckResult(level="warning", passed=True, message="Missing: pip install … — check not executed"), never an error. JPG/PNG/GIF/BMP/WEBP add a stdlib header fallback when Pillow is absent.

Data flow for one dataset

1Discoverlist_draft_datasets() via dvmeta or paginated search; CrawlWorker confirms locks + labels; cache-first paint, background diff reports N new, M updated, K removed.
→
2InspectDetail auto-loads (QTimer.singleShot(100), MetadataWorker): metadata, inventory, curation, diff, versions, timestamps, review submission.
→
3DownloadDownload All quotes (original size for tabular), skips fully-staged, streams bundle, fetches originals, drops .tab, verifies (ok, problems, warnings).
→
4CheckRun checks (CheckWorker → run_report): dispatch per file + dataset-level extensions; exports to workspace/downloads/<pid>/reports/.
→
5CurateMain column (completeness, manifest, auto-checks, version log) + sidebar (sections, timeline, assessment → pushes curation label). Header link is version-aware (…&version=DRAFT).
