Rust rewrite — advantages, disadvantages, fit

For Dataverse Docent (PySide6 desktop + Python check engine, 212 engine tests). Companion to ui-testing-research.html, which recommended staying on PySide6. This page evaluates the other language you asked about: Rust.

VerdictDon't rewrite the app in Rust. The two real Rust paths split apart: Tauri (Rust backend + web frontend) keeps most Python assets but trades Qt for a webview; the native Rust GUIs (Iced, Slint, GPUI, egui) are a full re-port with no testing advantage over PySide6. The one Rust move worth considering is PyO3 hotspots, not a rewrite. ConfidenceHigh for "no full rewrite" (migration cost is structural, not a judgment call). Medium on Tauri as a future shell — worth a prototype only if you ever need a web frontend anyway.

1. What "rewriting in Rust" would even mean here

There are two different Rust futures, and they look nothing alike:

PathWhat changesWhat survives
A. Tauri shell (Rust backend + webview frontend)PySide6 UI → HTML/JS (any web framework); Rust commands replace Qt signals/slots.The Python engine could stay as a sidecar, or move behind PyO3. Tests port per-layer.
B. Native Rust GUI (Iced/Slint/GPUI/egui)UI → Rust code in a new retained/immediate model; engine → Rust if you go all-in.Almost nothing. The kit, gallery, and theme are rebuilt from zero.

Dioxus sits between these: "React in Rust" rendered in a WebView on desktop (Wry) — web frontend economics with a Rust authoring model. Slint is the dual-licensed declarative option (free on desktop/web, GPL otherwise). GPUI is Zed's component framework, CSS-like API, still maturing outside Zed.

2. Advantages of Rust (honest list)

  • Bundle & startup: Tauri builds are 3–15 MB vs 85–200 MB for Electron, and clearly smaller than our PyInstaller lite folder (~174 MB). Rust cold start is under half a second vs Python import cost.
  • Memory & concurrency safety: no GC pauses, data-race-free threading (useful for the download/check workers), release-mode speed for the engine.
  • Library power, if you go all-in: Polars, Pydantic-core, orjson, DataFusion, Polars-in-Python — the industry pattern is Rust under Python (PyO3/maturin) for the hot 5%, which you already benefit from transitively through those libraries.
  • Single-binary story: one Rust binary replaces onedir folders, no interpreter, no DLL hell.

3. Disadvantages (also honest)

CostWhat it hits in our repo
Engine re-port212 Python tests covering R-ported checks (22 format modules + report contract + dispatcher). Every check becomes new Rust + new tests. Migration guides stress: keep test parity per commit, downstream consumers per downstream consumer.
UI rebuild from zeroKit (widgets.py), theme roles/contrast contract, gallery, table-layout persistence — the parts that currently stop regressions — all rebuild. Native Rust GUIs (Iced/egui/Slint/GPUI) also lack Qt's accessibility story (VoiceOver/NVDA, IME parity) that the 2026 survey calls out as the winners' edge.
Team / bus factorOne person learns Rust; the next curator-dev inherits a language they may not read. Python's library depth (scipy, pyreadstat, netCDF4/h5py in the full build) has no Rust equivalents at parity — the full build's heavy libs would stay Python anyway.
Timeline risk"Closer to a rewrite than a refactor" is the consensus line on Electron↔Tauri moves; a full Python→Rust move is larger. You pay the cost up front for perf you don't currently need (the window cap is 2,000 rows, cheap).

4. Fit verdict

Do not rewrite the app in Rust. The advantages that matter for us (perf, memory) aren't your bottleneck — your UI regression cycle is. Tauri would hand you a webview and force a frontend in JS, trading Qt's mature desktop conventions (and our existing test guards) for browser conventions you'd have to re-secure (allowlist, sandboxing). The native Rust GUIs remove the webview but also remove everything that makes the current app testable.

The narrow exception worth doing instead: if profiling ever shows a hotspot (e.g., file-format checks on big deposits), port that function to Rust via PyO3/maturin and ship it as an optional acceleration next to the Python implementation. That's the Polars/Pydantic pattern: one codebase you can read, Rust only where it earns the effort. Everything else stays Python.
