Phase 1 — Screenshot goldens (the visual gate)

Goal

A checked-in baseline + a CI diff that fails when the painted pixels drift. Catches the bug class that today needs a human glance: wrong tint after a token swap, clipped text, shifted headers, dead hover states.

Files to create

  • ui/tests/golden/baseline/*.png — baseline images (checked in).
  • ui/tests/golden/__init__.py + ui/tests/test_golden.py — the harness (new fixture golden_screenshot in conftest.py).
  • tools/probes/_common.py:golden_boot() — windows-platform variant of boot() reused by both probes and tests (deduplicate the temp-workspace rule).
  • ui/tests/golden/README.md — how to bless a change (pytest --update-golden) and the tolerance table.

Environment & determinism

  • Run with QT_QPA_PLATFORM=windows (real fonts). New CI job golden on windows-latest, not offscreen. Existing CI jobs stay offscreen.
  • Pin window size (1280×812, matching current probes), fixed DPI/scale (100%), disable window animations, freeze dynamic content (stub workers, empty queue, seeded rows) so only the paint can vary.
  • Capture via widget.grab() → QPixmap → PNG bytes. Compare with Pillow: per-pixel abs-diff with a threshold (fonts/AA ⇒ threshold, not exact). Default: fail if >0.5% pixels differ by >12/255, or any pixel differs by >64/255. Per-image overrides in the README table.

What gets captured (v1 set)

  • Dashboard (empty + seeded-with-rows), each page (Settings, About, Log, Review config), gallery page (the exhibit is the test), dataset detail header + Metadata check + File Manifest + Auto-Checks (seeded, one pass/one warn/one fail).
  • States: hover (simulate QMouseEvent), focus-visible (Tab into widget), disabled (primary disabled face), selected row. One state per golden; no combined states.

CI & failure UX

  • On failure, save *_actual.png + *_diff.png as CI artifacts, print the path. The diff is the review surface — a human decides "intended vs regression".
  • Blessing: pytest ui/tests/test_golden.py --update-golden rewrites baselines; the PR shows the baseline diffs like code.

Acceptance

  • Changing one token color fails exactly the goldens that paint it, with a readable diff.
  • Two consecutive CI runs on unchanged code pass (no flake).

Risks

  • Font rendering on the CI runner must match the dev machine. Mitigation: bless baselines on CI (download, review, commit), never from a dev laptop.
  • Baseline bloat: keep goldens few (≤12 v1). Each is a maintenance commitment.

Phase 2 — Behavior contracts (pytest-qt interaction tests)

Goal

Prove behavior, not just paint: click → state, Tab → focus tint, hover → tooltip, drag → layout. Turns every past one-off probe into a regression test that names the bug it guards.

Setup

  • Add pytest-qt to pyproject.toml dev deps; add qt_api = pyside6 to pytest config. Add a qtbot fixture (session-scoped, alongside the existing qapp/win in conftest.py) that registers widgets for teardown.
  • Use qtbot.waitSignal / waitUntil for async (workers, loaders) — never sleep loops.

Test suites (one file per past bug class)

FileContracts pinned
test_interactions.pyHeader casing ≠ elision (sentence-case label stored, elide-right, tooltip recovers full title); focusVisible only after Tab, never after mouse click; disabled primary face uses dark ink, never white-on-blue; split-chip elision + tooltip; sort-by header arrow; dirty-guard prompts on Settings and Review config.
test_gallery_contract.pyEvery kit kind/size/state exhibits in the gallery; BUTTON_OBJECTS ↔ button_qss() agree kind-by-kind (supersedes probe_buttons.py).
test_kit_exports.pyConformance: no view writes a stylesheet, names a raw palette entry, or builds a raw input widget (promotes test_theme_conformance.py invariants into the same file for discoverability).

Retention rule

  • Each test docstring names the bug: """Regression: sentence-case headers elided 1 letter (2026-10-02)."""
  • When a probe catches a new bug, port it to pytest-qt the same PR. Deleting a probe without its test is a review blocker.

Acceptance

  • pip install -e .[dev] && pytest ui/tests -q exercises every Phase-2 contract; a deliberate token-color change that should fail doesn't pass silently (it fails, golden or behavior depending on where it lands).

Phase 3 — Process (gallery as gate, PR discipline)

Goal

The kit + gallery + golden move together, so a new component can't exist without being exhibited and painted.

Changes

  • Gallery-in-CI: the gallery page is one of the Phase-1 goldens. A mixin change re-paints the gallery baseline; the PR shows the exhibit diff.
  • Coverage check: a static test (test_gallery_coverage.py) parses the kit's public API and asserts each public builder appears in ui/gallery.py. New builder without an exhibit fails the build.
  • PR checklist (in CONTRIBUTING.md or CI template): component → kit builder + gallery exhibit + golden + test, all in one PR. One-off setStyleSheet in a view is already forbidden by conformance tests; this extends the ban to "unexhibited kit change".
  • Probe lifecycle: tools/probes/README.md gains a "Promote or delete" rule with a 2-PR deadline — a probe lives max 2 PRs before it's a pytest test or it's deleted.

Acceptance

  • Adding a kit builder without a gallery exhibit fails CI on the new coverage test.
  • A gallery golden diff appears on every mixin-change PR, reviewable as images.

Agent-first (you + AI agents, one laptop)

The test system is operated by agents, not a CI farm. Three consequences:

  • Agents never bless baselines alone. An agent runs goldens, analyzes the diff, and proposes the change. Only the human runs --update-golden. Otherwise the gate blesses its own mistakes.
  • Diffs are reported as text first. The harness prints a human- and agent-readable summary ("dashboard_empty: 2.1% pixels changed, max delta 88, bounding box 40×12 at (120,44)") before any image. Images confirm; text reasons.
  • Fast, scoped commands. pytest ui/tests/test_golden.py -k dashboard for one surface; pytest -k "not golden" for the fast behavior suite. Everything runs offscreen except goldens.
  • Probes become tests same-PR. The retention rule (Phase 2) is the agent loop: probe discovers → port to pytest-qt → probe deleted. Nothing lives only in a probe file.
