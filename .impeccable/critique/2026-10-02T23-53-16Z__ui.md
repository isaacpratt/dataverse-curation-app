## Overall Impression

28/40 — a solid, above-average operational tool held out of the top band by one visibly broken control and state ambiguity. The shell has real desktop craft; the mid-flow (Settings→Extensions, the decision step) is where confidence leaks. ## Priority Issues

**[P0] Extensions action buttons render as dead, clipped outlines**
- What: In Settings → Extensions the Reinstall/Uninstall cell is 13 px tall while the buttons are 28 px at y=3 (needs ~34 px); `setRowHeight(row, 34)` runs after `setCellWidget`, and fragments paint over the "USED FOR" text.
- Why it matters: A reachable control that looks broken destroys trust on the exact screen users visit when something needs fixing.
- Fix: Set row height before `setCellWidget`, or wrap buttons in a fixed-height cell widget; verify `_CELL_BTN_STYLE` doesn't reset minimum size; re-capture to confirm filled buttons with labels.
- Suggested command: /impeccable polish

**[P1] Icon-only primary navigation**
- What: Settings, Configure Rules, Log, About are four bare glyphs in the title bar, identified only by tooltips/accessibility names.
- Why it matters: Recognition-over-recall failure — new/returning users decode 16 px icons to find core functions. (Context: deliberate density choice in the title-bar batch; the finding is that the cost lands on recognition.)
- Fix: Icon + always-visible label (slim rail), or a grouped menu affordance; keep tooltips as reinforcement only.
- Suggested command: /impeccable clarify

**[P2] "—" placeholders conflate loading, empty, and unfetched**
- What: Metric cards, status chips, the Signed-in user block all show "—" pre-crawl; dashboard shows bare "0 s".
- Why it matters: Users must infer whether the app is broken, loading, or never configured — direct hit on Visibility of System Status.
- Fix: Explicit states: spinner/"Checking…", "Not fetched yet" + Refresh, "No user returned"; label the metric ("Last refresh: never").
- Suggested command: /impeccable clarify

**[P3] Assessment Action combo: 5 visible options, non-answer default**
- What: "Select decision…" + 4 options — the widest decision point in the workflow, no helper text, no consequence preview.
- Why it matters: Highest-stakes control presented as the widest single choice; first-timers freeze or guess.
- Fix: Split into a labelled radio group or ≤3 options; one-line helper text per action; disable Record until a real option is chosen.
- Suggested command: /impeccable shape

## Persona Red Flags

**Alex (power user)**: icon-only nav costs him every session; broken Extensions cell blocks "fix and move on"; whole-line red/amber log with no inline legend forces colour-code recall. Positives: tabs + Sections rail + "Show all metadata fields" give fast multi-dataset hopping.

**Sam (first-timer/anxious)**: "—" everywhere pre-crawl reads as "setup failed"; 5-option decision combo with no consequence text → freezes; error dialog offers only "Retry" with no "what to check". Positives: plain-language error headline, 42-file/1.4 GB consent dialog, first-run "Open Settings" CTA.

**Riley (stress/accessibility)**: focus is a colour tint only — keyboard users can lose their place on dense tables; status/severity partly colour-only (log lines, chip tints). Positives: accessible names on icon buttons; native focusable table views.

## Minor Observations

- "Signed-in user" hint wraps into a cramped narrow block under the "—" fields.
- About page is the least-designed surface — plain bullets on an empty screen; a two-column layout + "Copy diagnostics" would fill it usefully.
- Dashboard footer cache hint floats like a warning but is styled neutral — make it a link/button.
- Response-page button row mixes icon+text and text-only at equal weight — promote one primary, ghost the rest.
- Detail-header actions vary between icon-only and text at the same level — pick one grammar.
- Empty log gives no "the log will populate when you run checks" nudge.
- Card legend is small grey text — hover-reveal per card would remove the need to read it.

## Questions to Consider

1. What state is "—" — could a small state badge next to each metric kill the ambiguity outright?
2. Is the Extensions cell-clipping systemic — any other `setCellWidget` + `setRowHeight` pairing with the same ordering bug?
3. Should the decision step be a two-step "choose → confirm consequences" dialog instead of an inline 5-option combo?
4. What's the deliberate density budget — would one row-height/density token sharpen tables, logs, and queue rows together?
