## Priority Issues (P0: none · 2×P1 · 2×P2 · 1×P3)

1. **[P1] Settings edits are silently discardable, while sibling panes are not.** *Why:* a pasted token + "Connected." evaporates on nav-away with zero feedback — opposite safety contracts from the same nav bar. *Fix:* port the `● unsaved` chip verbatim (dirty on field change, "Discard changes / Keep editing" prompt defaulting to Keep editing, plus a "Saved to config.json · 14:02" state line). → `/impeccable harden`
2. **[P1] Dataset detail has no stated sequence across six sub-surfaces.** *Why:* the Load → Download → Check → Respond order is pure recall in the app's densest screen; the decision-guardrail peak looks like one more control. *Fix:* a visible 4–5 step rail in the detail header (Metadata → Files → Checks → Response → Decision) reflecting live state, click-through to tabs, disable-but-explain downstream steps. → `/impeccable layout`
3. **[P2] TopNav discoverability rests on hover.** *Why:* with the footer link removed (user-requested), the first-run CTA is the only labelled route to Settings. **Note: "keep icon-only + tooltips" is a closed decision from the last batch** — recording, not reopening, unless reopened. *Fix if reopened:* persistent 10–11px micro-labels at desktop widths + permanent selected treatment. → `/impeccable clarify`
4. **[P2] The app's most reassuring messages are its quietest.** *Why:* "Reports saved…", "Connected.", the new `baseurl/alias: n/m datasets shown` line all render 11–12px muted — the peak-end moments read as residue. *Fix:* 13px high-contrast success/error treatment with icon prefix, persist completion messages until the next action. → `/impeccable typeset`
5. **[P3] Concurrent-task opacity.** *Why:* "Another task is already running — please wait…" names an invisible state, with no cancel. *Fix:* status-bar busy indicator naming the active task + elapsed time; cancel where workers support it. → `/impeccable harden`
